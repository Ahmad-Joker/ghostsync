# QR transfer: implementation notes (spec corrections made while implementing)
Branch `feat/qr-transfer`, baseline `fd9b9da`. Each entry names the spec fact that the implementation contradicted or left open, the correction, and where it was made. `review.md`, `review.json`, `resolution.md`, `preflight-review.md` and `resolution-2.md` are unchanged.

1. **Version 23 is never emitted (changed fact).** Spec: 988 bytes -> version 23 (requirements AC-QR-003-2, design 4.3, tasks 3.3). Observed: `jsqr` 1.4.0 decodes no version 23 symbol at level L (every mask, several contents); versions 1 to 22, 24 and 25 decode at L, and 23 decodes at M, Q and H. Whether `jsqr` or `uqr` is at fault was not isolated. `buildQrSymbol` re-encodes from version 24 when the encoder picks 23. Result: 988 bytes -> 24; the 971 to 1055 byte range uses version 24; the 1232-byte limit, the version cap 25 and the 117-module 1232-byte symbol are unchanged. Edited: requirements AC-QR-003-2 and its table row, design 4.3 row and 17.1, tasks 3.3, `src/symbol.ts`, `tests/symbol.test.ts`.
2. **Entry bundle contains one URL (changed fact).** Spec: no `https://` in `assets/*.js` (design 13.6, task 7.2). Observed: the entry bundle already carried the Yjs warning link `https://github.com/yjs/yjs/issues/438` before this feature. The dist check (D-QR-01c) asserts the decoder chunk has no URL and that the entry bundle's only URL is that link. Edited: design 17.1 only.
3. **R3 decided: cross-direction import guard.** Added AC-QR-008-9 and its table row (requirements), the design 8.3 bullet, and tests U-QR-10 (unit, both directions) and E2E-QR-05b (browser, both directions). Scan is disabled while ANY import is pending; a running scan stops when a FILE import starts; a file import is refused while a QR import is pending, in the controller and in the view.
4. **R4 decided: scope of duplicate detection.** The applied set records QR imports only. Written in AC-QR-008-4, L-7 (requirements), design 8.3, the QR panel (`DUPLICATE_SCOPE_NOTE`, U-QR-12), and `docs/progress.md`. U-QR-10 asserts that a file-imported capsule scanned by QR reaches `scanned`, imports again with an empty diff, and is then `already-imported`.
5. **`importFile` split.** Spec 8.1 named `importBytes(bytes, source, opts)` as a private method. It is public on `SessionController` because the QR controller calls it, returns `Promise<boolean>` (false when nothing ran), and shares one `beginImport` and `applyImport` with `importFile`. `onImportStart` was added next to `onSessionEnd` so a running scan can stop when a file import begins.
6. **Scan session restart on the same object.** Spec 7.2 step 1 said `start()` is ignored while `state !== "idle"`. Implemented: ignored while `requesting` or `scanning`; a terminal state (`denied`, `failed`, and so on) allows a new `start()`. The app also creates a new `ScanSession` per Scan, so the late-`getUserMedia` race is covered both on one session object (unit) and across session objects (E2E-QR-14).
7. **Deps types.** `ScanDeps.setTimeout` and `clearTimeout` are `(fn, ms) => unknown` and `(id: unknown) => void` instead of `typeof setTimeout`, so Node and DOM timer types do not conflict. `readFrame` was added to `ScanDeps` so the frame loop is testable without a DOM.
8. **Oversize message for QR.** `mapCapsuleError("OversizedRaw")` still says "larger than the 16 MiB limit". A QR import of more than 1232 bytes is rejected with that wording. A frame cannot carry more than 1232 bytes, so the user cannot reach it by scanning; it is reachable only through `importBytes` and is recorded as a gap, not changed (AC-QR-009-1 asks for the same message as a file import).
9. **E2E-QR-14 and E2E-QR-15 added.** E2E-QR-14 is the browser form of the Cancel and immediate re-Scan race (newer stream stays attached and live). E2E-QR-15 scans a real 1232-byte capsule at version 25 through the video path and imports it, and checks that the interior-space frame `GSQ1: 0` and the synthetic `GSQ1: 0 ` keep their space through the video, canvas and decoder. This closes the scan-side half of review finding R6; the show side is limited by what the app can build (a board of about 1232 bytes needs exact note padding by hand).
10. **Not implemented (stated, not hidden).** E2E-QR-13 (fake-device flags, SHOULD), the 1854-character raster in the browser, tasks 8.10 (fresh-snapshot run), and all of task 9 (physical test, EV-PHYS NOT RUN).
